# Diagram generation

Use the installed `zudo-diagram-gen` CLI and public engine APIs. Author SVGs yourself or through explicitly assigned authors outside the engine; the CLI does not generate artwork or call a model. Accept caller paths. Keep personal destinations and `/my-diagram-gen` policy outside this core.

1. **Ground the request.** Read the actual feature and supplied sources. Write Intent, Must show, May drop, References, Lock, Target, Language and fonts in the brief. Record exact labels/facts, original or invented provenance, redistribution authority for assets, explicit constraints and target CSS dimensions. Treat `session.json.target` as authoritative; reconcile it before drawing. Ask only for material missing facts. Choose one diagram when requested; otherwise agree a bounded exploration (default at most four candidates).
2. **Create or resume.** Read [commands](references/commands.md). Use `new --out <new-directory> --brief <file>`; add `--project` for a registered multi-session host. Installation is opt-in. For `--session <existing-directory>`, use `resume <directory> [--review <file>] --json`. Never combine create and resume, overwrite existing work, initialize Git or install a personal skill. Inspect partial results before repairing them; preserve healthy siblings.
3. **Resolve the visual context.** Use `tones show <id> --json-version 1` to read bundled meaning, full examples, scheme and kit. Read the actual reference images with an image viewer. Missing optional scheme/kit means hand authoring remains available; a declared missing resource is a blocker. If a project style is locked, read its immutable snapshot and palette through the public API; do not substitute the current catalog. Keep actual target size, label language and font requirements in view.
4. **Author saved candidates.** Read [authoring and ownership](references/authoring.md). Keep SVGs self-contained with literal colors, `viewBox`, title and description. Materialize semantic kit roles through the public API when useful; hand geometry is allowed. Give every candidate a stable unique session-local ID. Do not claim structural validation certifies facts, tone adherence, glyph coverage or readability.
5. **Validate, capture, then inspect.** Run `check <root> --json-version 1`. Capture each proposed light/dark candidate at its real placement with `capture ... --json`. Then actually open each resulting PNG with an image-viewing tool and assess labels, facts, overlap, contrast, geometry, fonts and fit. Capture sidecars retain `inspected:false`; capture success is not image inspection. Record a separate evaluator note naming image hash, candidate fingerprint, theme, placement, browser/fonts and observed findings. Never invent an inspection or approval. Use at most two correction rounds; preserve partial results and report remaining blockers with exact recovery commands.
6. **Transfer a review explicitly.** Present concrete saved candidates/images. Consume the user's named choice or copied/downloaded review JSON with `inspect/resume --review`. Browser storage is inaccessible to this CLI. Stale evidence requires actual inspection and renewed explicit review; retain earlier notes and IDs. A test selection is never user approval. Choosing a drawing does not adopt a project-wide style.
7. **Refine the saved baseline.** Read the selected saved SVG, exact fingerprint and keep/change feedback. Use `createRefinement` with a new ID in a later round and that saved parent. Preserve accepted facts and geometry before editing only requested aspects. Keep earlier candidates intact. Recheck, recapture and actually inspect changed images; deliberately update saved asset hashes after edits. For explicit project style adoption, use the separate selection/lock/adopt workflow in the command reference.
8. **Export the saved result.** Export the exact named candidate/theme through `export`, passing explicit `--resource-root` for a nested project session. Never regenerate at export time. A direct one-diagram request authorizes delivery of the inspected saved drawing; identify it as unapproved if the user has not reviewed it. Integrate only when the request authorizes it. Report candidate ID, lineage, export path, checks, actual visual observations and unresolved limits.

For a five-session sweep, missing browser, stale evidence, review transfer or style adoption, read [scenario recovery](references/scenarios.md). Maintain one tone author across sessions, one writer per candidate directory, and coordinator ownership of shared metadata. Bound retries and resume partial work without silently dropping requested sessions.
