# Content and ownership

Read generated AGENTS.md and installed JSON schemas before edits. A session has session.json, brief.md, rounds/<round>/round.json and rounds/<round>/<candidate>/candidate.json plus saved SVGs. Candidate metadata carries schemaVersion:1, id, title, toneId, description, order, assets:{light:'light.svg',dark?:'dark.svg'}, parentCandidateId:null or an earlier-round candidate ID. Asset paths are candidate-relative. IDs remain stable and globally unique within that session; identical IDs may occur in different project sessions.

Keep target dimensions authoritative in session.json. A placement frame/slot uses CSS pixels and contain fit; slot width/height must equal target. Use real context, allowed local images and fonts; invented sources must be identified. Project manifests register sessions/<slug> and exact persisted session IDs. Comparison entries are explicit sessionId/candidateId/fingerprint mappings, never first/latest tone matches.

A coordinator owns project.json, session.json, briefs, round.json, comparison mappings and style selections. Each candidate directory has exactly one writer. In a tone sweep, assign one tone author across all sessions so tone interpretation is consistent; each author writes only assigned candidates, reports IDs/fingerprints/results, and never edits shared metadata. The coordinator stages metadata in a sibling temporary file and atomically renames it after validation, preserving competing/user changes. A failed worker must not overwrite healthy siblings or remove their comparison mappings. Mark missing/invalid/stale entries explicitly, retain resumable partial work and retry only assigned failures within the bounded correction budget.

Resolve installed tone context rather than cwd/private references. Read required local meaning, complete examples, scheme roles/rules and kit primitive inventory. Prefer semantic palette materialization; changing palette is not permission to change geometry. Required rules remain acceptance obligations; explain deliberate departures from preferred rules. Structural checks cannot certify descriptive rules.

Use standalone literal SVGs with no external CSS/fonts/kit links, scripts, animations or remote resources. Inline materialized kit instances with namespaced IDs and rewritten local references through materializeKit. Preserve hand-authored geometry when resolving palette roles. Use explicit light/dark assets; unavailable dark has no light fallback. Keep semantic labels/facts readable at final slot dimensions; nominal typography checks do not prove actual glyph coverage or text fit.

After a review, copy the actual selected drawing into a later-round child using createRefinement. Preserve geometry and facts until deliberately changed. Keep originals, browser feedback and fingerprints intact. Hashes for style/placement/capture are separate from artwork fingerprint; missing new evidence is unknown. Capture is never inspection. Record actual evaluator observations separately, keyed by the captured PNG bytes and input provenance. If those inputs change, recapture and inspect affected evidence rather than recycling earlier claims.
