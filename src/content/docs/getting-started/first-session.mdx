The initializer creates a small private project with session metadata, a brief, an initial round, zfb configuration, and package scripts. Its empty gallery is ready for an agent to add candidates.

## Initialize from this source handoff

In the downloaded repository, create local package archives:

```bash
pnpm pack:local
```

Copy the absolute path of the engine archive printed by that command, then run:

```bash
node packages/create-zudo-diagram-gen/bin/create-zudo-diagram-gen.mjs \
  ../my-diagram-session \
  --name "Feature help diagram" \
  --engine-package /absolute/path/to/the/engine-package.tgz \
  --yes

cd ../my-diagram-session
pnpm install
pnpm dev
```

Use an absolute path for a local engine archive so the generated project can resolve it from its own directory. Keep that archive available while the host depends on it. You can switch to a published package version later, when publication has actually happened.

The initializer does not install dependencies unless `--install` is supplied. It does not initialize Git or install an agent skill. `--yes` is accepted for automated callers; this initializer does not require an interactive interview.

## Establish the brief

Edit `brief.md` before generating a batch. State:

- The one idea the reader should understand.
- The real states, actions, or relationships involved.
- Exact user-facing labels and relevant source references.
- The expected diagram size and surrounding help context.
- What this round should explore, and which facts must stay fixed.

Set `target.width` and `target.height` in `session.json` to the intended CSS-pixel dimensions of the placement preview. Set `context.title` and `context.body` when a nearby heading and explanation will help you assess the drawing.

## Add a candidate

Create a directory such as `rounds/r01/c01/`. Add `candidate.json`:

```json
{
  "schemaVersion": 1,
  "id": "r01-c01",
  "title": "Fine outline",
  "toneId": "fine-outline",
  "description": "A quiet treatment with a direct reading order.",
  "order": 1,
  "assets": {
    "light": "diagram.light.svg"
  },
  "parentCandidateId": null
}
```

Add a complete SVG at `rounds/r01/c01/diagram.light.svg`. This small example is enough to exercise the gallery; replace its explanation with the real feature before using it in application help.

The asset path is relative to the candidate directory. A dark-theme asset can be declared as `assets.dark` when a corresponding file exists.

The running session detects metadata and SVG changes, including newly added candidates. A partially written or invalid file must be corrected before the new session state can be prepared successfully; run the validation command for a readable diagnosis.

## Validate and review

```bash
pnpm check
```

Open the gallery, inspect the drawing, and check the placement preview. Generate additional candidate directories to explore other approaches. Keep IDs stable so feedback can continue to refer to the same drawing.

Use the gallery's copy-feedback or review-download action to pass your decision to the agent. A refinement belongs in a later round with a new candidate ID and a parent reference to the chosen baseline.

## Export a chosen drawing

```bash
pnpm exec zudo-diagram-gen export r01-c01 \
  --session . \
  --theme light \
  --out selected-diagram.svg
```

The SVG export copies the selected declared asset. It does not automatically integrate it into another application. Read [SVG authoring](/docs/authoring/svg-authoring/) for theme, accessibility, and destination considerations.
