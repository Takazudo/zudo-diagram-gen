The downloadable source is intended to continue locally with Codex. The repository's `AGENTS.md` describes shared conventions, and `docs/CODEX-HANDOFF.md` gives the implementation map and remaining work.

## Automated contract checks

From the project root:

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm check:examples
pnpm build
```

The important risks are invalid metadata, missing assets, duplicate IDs, incorrect lineage, paths escaping a candidate directory, incomplete package contents, and a generated host that accidentally relies on the monorepo. Test these contracts when changing their implementation.

Repository CI uses Node.js 24.13.0 and pnpm 10.30.3 for these commands on pull requests and main. A passing workflow covers the automated gates; it does not replace a real-browser review or the fresh installed-consumer check.

SVG validation establishes that a file meets the supported format. Visual review must still check labels, clipping, line weights, contrast, and the explanation itself.

## Verify the packed consumer

Run `pnpm pack:local`, initialize a fresh host outside the repository with the engine archive, install dependencies, add a valid candidate, and run its check and build commands.

Also exercise the empty initial gallery. An agent needs to be able to start the viewer before it has finished writing the first SVG.

## Browser acceptance checks

Use a real browser at a desktop width and a narrow width. Check:

- Overview, inspect, and compare navigation; candidate and round filters; stable IDs.
- Theme availability and independent backdrop controls.
- Fit, 100%, zoom, pan, and placement preview dimensions.
- Keyboard operation and focus without stealing keys from text fields.
- Shortlist and chosen-direction state, feedback text retention, and next-action selection.
- Copy feedback, review download, same-session import, and stale-content feedback.
- Candidate additions, edits, and removals while the session server is running.
- SVG and offline HTML exports opened independently.

A successful build does not prove these interactions. Record any unavailable browser verification as a remaining check, with reproduction steps.

## Demonstration lineage

The ten-candidate example includes a second-round outline refinement to demonstrate parent references and navigation. It is an authored example, not a record of a user's actual selection or approval.

## Publication and skills

The package versions and local archives support testing this handoff before publication. The repository and packages have MIT license files, but repository/homepage/bugs package metadata and the differing copyright holder text still need release review. Confirm registry ownership, complete that metadata, and pass a fresh packed-consumer build before publishing. Neither package nor the site is published by this handoff.

The `/diagram-gen` and `/my-diagram-gen` pages are an integration design. Implement the actual Claude Code skills in the user's chosen skill repository after exercising the app in a real project. The core receives an explicit destination; the wrapper resolves personal output conventions.

## Report verification accurately

The handoff verification report records commands actually run and their results. Keep it current when continuing locally. Distinguish static SVG inspection, automated contract tests, zfb builds, packed-consumer checks, and browser interaction checks instead of combining them into an unqualified “tested.”
