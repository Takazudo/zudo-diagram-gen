The engine archive includes `skills/diagram-gen/SKILL.md` and three focused references: `commands.md`, `authoring.md`, and `scenarios.md`. These are available files, not evidence of installation or automatic discovery in your personal agent host. Use [Local archive setup](/docs/getting-started/local-archives/#optional-project-local-skill-copy) to resolve the installed file, copy a project-local directory if wanted, and verify your host's mechanism. You can always explicitly ask the agent to read that file and its references.

## Actual core workflow

The core grounds facts, writes the improved brief, creates or resumes a caller destination, resolves actual tone resources, authors saved candidates, checks them, captures and **opens** resulting images, transfers explicit review, refines a named saved baseline and exports exact assets. CLI commands do not generate SVGs or call a remote model; authors operate outside the engine. Read the full [workflow](/docs/agent-workflow/iteration/) and [command reference](/docs/reference/cli/).

The packaged skill's invocation hint is:

```text
--out <new-directory> --brief <file> | --session <existing-directory> [--review <file>]
```

When your host has verified discovery, use `/diagram-gen` with those arguments. They express an agent task, not an executable binary. Use one create or resume mode. Supply `--out` and actual brief to the CLI's `new`; map `--session` to CLI `resume`. Natural-language context and candidate count guide the author rather than becoming invented CLI options. The CLI has no `--count` or `--tones` generation flags.

For explicit file invocation without discovery:

```text
Read .claude/skills/diagram-gen/SKILL.md and its references.
Use --session . and the attached downloaded review.
Preserve the named saved SVG's layout and labels; simplify only its arrows.
```

One diagram is appropriate when requested. Otherwise choose a bounded exploration, default at most four. Read project behavior before drawing, record public/original/authorized asset provenance, and inspect final label language and fonts at the real CSS placement. A check or screenshot cannot certify facts, readability, tone character or user approval. The skill limits correction rounds to two before preserving partial work and reporting blockers.

## Thin entry point, detailed references

The installed `references/commands.md` covers versioned envelopes, no-overwrite setup, review inputs, capture prerequisites, baseline API and explicit style adoption. `references/authoring.md` covers schemes/kits, semantic materialization and writer ownership. `references/scenarios.md` covers one diagram, five sessions, unavailable browsers and stale evidence. The corresponding public references are [CLI](/docs/reference/cli/), [API and schemas](/docs/reference/api/), [projects](/docs/authoring/projects/), [tone context](/docs/authoring/tone-context/) and [placement/capture](/docs/reference/placement-capture/).

For multi-session work, one tone author coordinates that treatment across sessions, one writer owns each candidate directory, and a coordinator alone owns project/session/round metadata and exact comparison mappings. Preserve healthy siblings if a worker fails; inspect and resume partial work rather than recreating or silently dropping requested sessions.

## Personal wrapper remains outside this delivery

A personal `/my-diagram-gen` wrapper may resolve a preferred output location and host defaults, then pass concrete caller paths to the core. This repository does not supply or install that personal wrapper. Personal helpers, home-directory layouts, networking policy and output conventions belong there; avoid duplicating the core's drawing logic.

MCP, model services, browser-to-source write endpoints, automatic conversation resume and automatic product integration are outside this delivery. Ordinary browser review needs explicit copied/downloaded input. Project style reuse needs explicit lock/adopt intent independently of selecting a drawing.
