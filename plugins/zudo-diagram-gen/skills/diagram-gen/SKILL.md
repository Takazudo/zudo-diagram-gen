# Diagram generation in a host conversation

This skill uses the files bundled beside it. It does not require the zudo-diagram-gen engine, Node, pnpm, a local server, an MCP connection, or a source checkout. Use the host's available file, render, and image-viewing tools. The user’s explicit instructions and supplied facts take precedence over stylistic guidance.

1. **Ground the drawing.** Read supplied source material and any attached baseline. Establish intent, audience, exact facts/labels/relationships, what may be omitted, target CSS width and height, theme, language, font availability, and rights for supplied third-party assets. Do not infer unknown product facts or translate locked labels. Ask only for missing information that materially changes the explanation. Make one finished drawing when requested; otherwise explore at most four candidates by default.
2. **Choose and resolve tone context.** Read only [`tones/catalog.json`](tones/catalog.json) first. Pick a relevant tone with the user’s requested style taking priority. For each selected tone, read its catalog entry’s `bundledReferences`, `scheme`, `kit`, and `referenceFiles`, plus its `source.svg` if useful. Resolve paths from `tones/`. Read the actual bundled SVG examples with an image viewer when available. Read [`references/tones.md`](references/tones.md) for scheme placeholders, rule precedence, font/size checks, and reuse limits. External source URLs are optional provenance, never a dependency for the explanation.
3. **Author and save.** Keep one stable ID per candidate, a brief, and a record of tone and target size. Follow [`references/artifacts-and-review.md`](references/artifacts-and-review.md). Write original, complete SVG files with explicit `viewBox`, `<title>`, `<desc>`, literal resolved colors, and local IDs. Preserve exact labels and relationships. Avoid scripts, animation, external stylesheets, remote fonts, externally loaded images, and references to bundled kit files at runtime. If using kit shapes, copy needed geometry into the SVG and keep local references valid. Do not present example artwork as if it were newly authored for the user.
4. **Check what can actually be checked.** Check SVG syntax and references if tools exist. Render each candidate at the target size and required theme if tools exist. Actually open the resulting image and inspect facts, labels, font glyphs, overlap, contrast, arrows, and fit. State separately what passed a syntax check, what rendered, what you personally inspected, and what the user approved. A successful render does not establish visual inspection, factual accuracy, or approval. Make up to two correction rounds, preserving earlier files.
5. **Deliver concrete artifacts.** Attach the exact saved SVG and, when rendering is available, an actual raster preview. Identify candidate ID, tone, target size, checks, visual observations, and unresolved limits. A downloadable result means a real host-provided file attachment; do not invent a link or claim permanent hosting. If file output is unavailable, offer SVG source as a clearly labeled reduced fallback. If rendering or image viewing is unavailable, say precisely which verification remains pending; do not call the result visually verified.
6. **Review and refine.** Record the user’s named choice and Keep/Change notes. A choice names this drawing’s saved baseline, not project-wide style approval. Read the exact chosen SVG bytes before editing; create a new revision ID with a parent pointer to that candidate, and retain the original unchanged. Preserve accepted characteristics while applying requested changes. Recheck, render, inspect, and attach the new exact saved file. Export or redeliver the selected saved bytes without regenerating from a tone recipe. For a new conversation, require the exact saved SVG plus its ID and relevant feedback to be attached; never assume access to an earlier conversation’s files. See [`references/artifacts-and-review.md`](references/artifacts-and-review.md) for stale or missing baselines.

For an optional advanced local application workflow, use [`references/local-engine.md`](references/local-engine.md). That route is separate and requires the installed engine and its own explicit setup. Never make it a condition of this conversational workflow.
