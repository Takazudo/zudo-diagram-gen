## Resources and transition

`packages/diagram-gen/tones/` is the installed resource root, resolved from the engine module, never from cwd or a home directory. Catalog `referenceFiles`, `scheme` and `kit` paths and `bundledReferences[].path` are relative to that root. A tone uses `<toneId>/scheme.json` and `<toneId>/kit.svg`; shared meaning lives in `shared/`. A descriptor is `{id,title,path,required:boolean}`. At least one required local explanation must resolve per tone after P01. `sourceReferences:[{title,url}]` remains optional HTTP(S) inspiration; local paths never become URLs. Required meaning cannot depend on a public website either.

Reads reject absolute paths, backslashes, NUL, empty/dot/parent segments, realpath/symlink escape, non-files, invalid UTF-8 and oversize files. JSON/Markdown limit 1 MiB, SVG limit 16 MiB; kit uses the same SVG resource policy. Missing optional references yield diagnostics; missing required references fail validation. Package `files` includes tones, schemas and source; archive verification checks every required resource, not only directory inclusion. Live-link auditing is separately invoked and distinguishes unreachable, redirect, rate limit and unknown visibility.

During P02/P03, legacy catalog entries without `scheme`/`kit` still load. Resolved context reports `capabilities:{scheme:false,kit:false}` and diagnostics; it never invents a scheme. A declared resource that is missing/malformed is an error. `requireComplete` is an explicit completeness gate, off for legacy/pilot reading and on for the bundled catalog at P09. All 24 IDs then require scheme, kit, explanation, recipe, source and light/dark references. User sessions with custom/legacy tones remain valid; completeness does not rewrite their artwork.

`resolveToneContext(toneId, options?)` returns existing tone fields and complete `examples` plus `contextVersion:1`, capabilities, resolved bundled reference content, scheme, kit text/primitive inventory and hashes. Optional missing resources are explicit. `tones show --json` retains existing top-level fields and adds context; list stays concise. Portable data contains package-relative paths only.

## Scheme and hashing

`schemaVersion:1` is format identity, `toneRevision` is an authored nonempty revision, and `collectionVersion` is catalog release identity. Neither is a content hash. `toneId` must match the catalog entry. `coordinateSystem:{viewBox:[x,y,width,height],units:"svg-user-units"}` uses finite coordinates and positive extents. Geometry numeric roles are finite, nonnegative user units; opacities are 0–1. Palette roles are exactly `ink,surface,border,accent,deep,warning`; each has a literal `#RRGGBB` value in `palette.light` and `palette.dark`. Overrides must resolve all roles in both themes; unknown roles and unresolved values fail. Semantic color remapping is allowed; changing geometry is not an implicit consequence of changing palette.

`geometry` contains role maps `strokeWidths`, `radii`, `fills` (palette role names), `opacities`, and `layers` (objects with finite `dx,dy,opacity`). `typography` maps roles to `{fontFamily,fontSize,minCssPx,fontWeight}`; size is positive user units, minimum positive CSS pixels, weight integer 100–900. `texture:{kind,seed,amplitude,frequency}` uses a nonempty kind, nonnegative safe-integer seed, nonnegative finite amplitude/frequency. No texture is `{kind:"none",seed:0,amplitude:0,frequency:0}`. `composition` records nonempty descriptions for `arrows,people,empty,pending,emphasis,warning`. `rules:{required:[],preferred:[],flexible:[]}` contains `{id,description}` rules with unique IDs across groups. Required rules are acceptance obligations; preferred rules can be deliberately departed from with a reason; flexible rules explain author freedom. Structural validation cannot certify descriptive rule adherence.

Recipes retain intent and examples. Once a scheme exists, numeric recipe summaries must be generated from scheme values or checked against explicit role references; independent duplicated numeric authority is forbidden. Existing explanatory recipes are not replaced with an imported spacing/color system.

For contain placement, nominal final scale is `min(slot.width/viewBox.width,slot.height/viewBox.height)`. A typography role's nominal CSS size is `fontSize * scale`; compare with `minCssPx`. This is only a nominal check: transforms, text shaping, overlap and arbitrary hand geometry require actual image inspection.

Canonical JSON hashing: recursively sort object keys by Unicode code-point order, preserve array order and strings exactly, serialize with JSON number/string semantics and no whitespace, encode UTF-8 without BOM, then SHA-256 lowercase hex. Reject nonfinite/non-JSON data; normalize negative zero as JSON does. Hash documents without their derived hash fields. Scheme hashes use this projection; kit and SVG asset hashes use original validated bytes, including BOM/newlines. Bundled-content hashes use original UTF-8 bytes. Tone context hash canonically hashes `{toneId,toneRevision,collectionVersion,schemeHash,kitHash,bundledReferenceHashes}` with reference hashes ordered by descriptor ID. Different canonical object key order must not change a hash; array/content/role/revision changes must. Do not substitute canonical hashing for legacy fingerprints.

## Kit and immutable style

Kit root is ordinary SVG with `viewBox`; primitives are `<symbol id="person|pin|slot-card|empty-seat|arrow|check|clock" viewBox="...">`. Each required primitive is present or has a documented tone-native alternative in scheme `primitiveAlternatives:{primitive:description}`. Palette-bearing elements use `data-palette-fill="role"` and/or `data-palette-stroke="role"` with literal defaults for inspectable source artwork. Materialization reads these attributes, substitutes resolved literal colors and removes markers; it never blindly substitutes all equal colors. Symbols and shared defs may contain local gradients, masks and clips.

`materializeKit` namespaces every instance's IDs and rewrites local `href`/`xlink:href`, `url(#id)` presentation/style references and token lists in `aria-labelledby`/`aria-describedby`. Unsupported reference syntax, duplicate/dangling IDs, external CSS/resources, script/animation and unresolved roles fail explicitly. Inline needed symbol geometry/defs into the final self-contained SVG before review; no external `kit.svg#id` and no rendering-time palette dependency. Hand-authored geometry remains permitted.

A project style reference is `{revision,path,hash}` pointing to `styles/<revision>/style.json`. Revisions are immutable URL-safe slugs; create never overwrites. Snapshot layout: `style.json`, `scheme.json`, `kit.svg`, `palette.json`. Style metadata includes `schemaVersion:1,revision,toneId,toneRevision,collectionVersion,schemeHash,kitHash,paletteHash,targets,typography,baselines` where baselines are explicit `{sessionId,candidateId,fingerprint}` entries and targets are session-qualified dimensions. Snapshot hash canonically covers metadata plus constituent hashes. `candidate.provenance` may contain `styleRevision,styleHash,schemeHash,kitHash,paletteHash`; absent provenance is legacy/unknown, never fabricated compliance.

Lock requires an explicit selection file with `schemaVersion:1,kind:"explicit-selection",purpose:"test"|"user",baselines:[...]`; validate all IDs/fingerprints and tone compatibility. Purpose test is never user approval. Choosing a drawing, shortlist, comparison switching and capture cannot lock style. A changed palette/kit creates a new immutable revision; `project adopt` explicitly updates the project reference after validation. Stage revision files then publish atomically; refuse conflicting/partial existing revisions and preserve them for diagnosis. No upgrade mutates an old snapshot. Refinement copies the named saved SVG into a new earlier-round child lineage, preserving accepted facts and geometry; export copies the saved validated bytes without regeneration.

## Project, identities and review compatibility

`project.json` has `schemaVersion:1,id,title,sessions:[{id,path,order,placement?}],comparisonSets:[{id,title,toneId,entries:[{sessionId,candidateId,fingerprint}]}]` and optional `style`. Session paths are project-relative `sessions/<slug>`; their persisted session IDs equal manifest IDs, orders are unique nonnegative integers and IDs are unique. Placement paths are relative to the project root. Style paths are likewise project-relative. Candidate IDs may recur across sessions; identity is `(sessionId,candidateId)`. Parent/baseline lineage remains inside its ordinary session.

`loadProject(root,{strict:false})` composes `loadSession`, returning `kind:"project",schemaVersion:1,project,sessions,comparisonSets,diagnostics,ok,contentHash`. Each session entry has `id,path,status:"valid"|"invalid"|"missing"|"stale",data|null,diagnostics`; last-valid retained data is explicitly stale with its observed hash. A manifest-level unsafe path/version/duplicate identity fails before traversal. `validateProject` and strict build require all registered sessions and comparison coverage valid; inspect/dev/export may show partial states but return `ok:false` and diagnostics. One host has project overview and session routes; generated-route ownership protects hand-written/modified files and only prunes unchanged owned routes. Watch project/session/brief/round/candidate/placement/style add/edit/remove/re-add and invalid→valid recovery without scanning unregistered content.

Each set maps every intended session to one exact candidate/fingerprint; omitted entries are missing coverage, duplicates are errors, tone mismatch invalid, fingerprint mismatch stale, absent theme unavailable. Never infer first/latest matching tone. Empty comparisonSets are valid during scaffolding. Offline project HTML keeps all these states visible, bundles permitted resources and enforces a 64 MiB output-data budget; exact SVG export remains single-session.

Existing candidate `fingerprint` stays SHA-256 of `JSON.stringify` of the existing fixed normalized projection in source order: `id,roundId,title,toneId,description,order,parentCandidateId,sourcePath,assets`. Additive provenance/style/placement/capture fields are excluded. Preserve current session IDs, storage keys and version-one `zudo-diagram-review` imports. A legacy fingerprint is compared to this same projection; do not recompute it with sorted keys or require new metadata. Changed bytes or existing fingerprint fields mark artwork review stale. Keep notes/selection snapshots visible, never auto-update their fingerprints to imply approval. New separate `assetHashes,styleHash,placementHash,captureHash` express their own provenance/staleness. Style changes with unchanged saved artwork mean style-conformance unknown/stale, not erased artwork feedback. Missing new metadata means unknown. Project review format `schemaVersion:1,type:"zudo-diagram-project-review",projectId,sessions:[ordinary version-one session review]` preserves session-qualified import boundaries and rejects foreign/duplicate sessions. Ordinary imports continue to validate session ID and candidate existence.

## Placement and capture

`placement.json` is `{schemaVersion:1,frame:{width,height,background},slot:{x,y,width,height},fit:"contain",fonts?:[fontFamily],context?:{title,body},images?:[{path,x,y,width,height}]}`. Coordinates/dimensions are CSS pixels; finite dimensions >0 and <=20000; x/y >=0, slot/images within frame. Slot width/height exactly equal authoritative `session.target`; conflict fails. Missing descriptor defaults to target-sized frame, origin slot and theme-appropriate background. Background is literal `#RRGGBB` or `transparent`. Contain centers artwork and never crops it. Images resolve against descriptor directory within session/project root; only explicitly supplied local allowed image files, no arbitrary URLs, symlink escapes or source leaks. Shared placement renderer uses isolated image-element SVGs for both viewer and capture.

Capture API `captureCandidate(sessionRoot,candidateId,{placement?,theme?,output,dpr?,crop?,timeoutMs?,browserExecutablePath?})` uses theme light by default, DPR 1 default (finite 0.5–4), crop `frame|slot` default frame, 30s default timeout (1–60s), max rendered 40 million physical pixels, 16 MiB individual images and 64 MiB combined inputs. Wait for image decode plus declared font readiness; freeze animation, block network and reject unavailable theme. Report detectable overflow/readiness failures and limitations: fonts-ready does not prove Japanese glyph coverage or readable labels.

Output PNG plus `<output>.json` provenance includes `schemaVersion:1,sessionId,candidateId,fingerprint,assetHash,styleHash|null,placementHash,theme,crop,frame,slot,dpr,pixelDimensions,browser:{name,version},environment:{os,fonts},capturedAt,inspected:false`. Snapshot all inputs used; image byte hash belongs in evidence metadata. Inspection is a separate evaluator record, never implied by capture or set as user approval. Candidate/theme/style/placement/DPR/font/browser changes stale applicable evidence. Cross-machine pixel equality is not a quality gate.

Capture distribution: optional peer `playwright` pinned/tested at 1.59.1 and lazily resolved from the installed consumer. Explicit setup is `pnpm add -D playwright@1.59.1` then `pnpm exec playwright install chromium` (OS dependencies separately if needed). No postinstall/browser download on ordinary commands, no root-dev dependency assumption. A caller may explicitly supply a local `browserExecutablePath` (CLI `--browser-executable <path>`) for an existing system browser; validate that it is an executable regular file, record its actual version, and never modify global browser configuration. A system browser may differ from pinned CI; report that substitution. Missing library/browser yields `CAPTURE_UNAVAILABLE` with these recovery commands; check/tone/export remain browser-free. Capture owns and closes its temporary server/context/browser on success, error or cancellation. All new export/capture operations refuse existing destinations unless `--force`; even force cannot overwrite source/metadata/style/placement through lexical or realpath aliases. Protect the sidecar too. Existing SVG export overwrite behavior remains compatible for nonsource outputs; strengthen HTML source protection without breaking valid forms.

## CLI, scaffold and brief

Planned stable forms (existing forms remain valid):

```text
new --out <dir> --brief <file> [--project] [--install] [--json]
inspect <session-or-project> [--review <file>] --json
resume <session-or-project> [--review <file>] --json
tones list [--json] [--json-version 1]
tones show <id> [--json] [--json-version 1]
capture <candidate-id> --session <dir> [--placement <file>] --out <png> [--theme light|dark] [--dpr <n>] [--crop frame|slot] [--browser-executable <path>] [--force] [--json]
project lock <dir> --tone <id> --palette <file> --selection <file> --revision <id> [--json]
project adopt <dir> --revision <id> [--json]
check|dev|build|preview <session-or-project>
export <candidate-id> --session <dir> --theme light|dark --out <svg>
export-html <session-or-project> --out <html> [--force] [--json]
```

Inspect/resume load files and supplied review only, never inaccessible browser storage. They do not regenerate content or invoke a model. `new` creates empty content/host state, not artwork; create and resume destinations cannot be combined. The engine owns the single authoritative `src/scaffold.mjs`; initializer is a thin adapter using a generated bundled copy of that same source. Checked generation/prepack verifies the copy, and initializer archives include it so unpublished `npm exec` plus `--engine-package <tgz>` does not require an unpublished registry engine dependency. No independent templates, engine→initializer dependency or circular dependency. Both reuse safe createProject logic, exclusive writes, empty-destination/symlink refusal, rollback only owned files and opt-in installation. Engine template supports project and single-session hosts; retain zfb 3 zudo-react and zfb 2 Preact consumers, root zfb 2 documentation host. Core skill ships at engine `skills/diagram-gen/SKILL.md` with bundled references via package files; no personal install as a side effect.

New commands' `--json` and legacy commands' opt-in `--json-version 1` emit exactly one envelope `{schemaVersion:1,command,ok,data,errors:[{code,message,path?}],warnings:[{code,message,path?}]}` to stdout. Existing check/tones bare `--json` shapes retain their fields; do not silently replace them. Human diagnostics and install/zfb child logs go to stderr in machine mode. Exit 0 success, 1 validation/incomplete/stale acceptance failure, 2 usage/unknown flags/version, 3 missing optional capability, 4 I/O/resource/unsafe-output/conflict failure, 130 cancellation. Codes: `VALIDATION_FAILED,INCOMPLETE_PROJECT,STALE_INPUT,INVALID_ARGUMENT,UNSUPPORTED_VERSION,CAPTURE_UNAVAILABLE,RESOURCE_UNSAFE,OUTPUT_CONFLICT,IO_ERROR,CANCELLED`. Legacy failure exit 1 remains for legacy forms; new/versioned forms use this map. Reject unknown/duplicate options. Dev/build/preview retain their normal log stream; no claim of JSON support for long-lived commands.

Scaffold `brief.md` headings are Intent, Must show, May drop, References, Lock, Target, Language and fonts. Meaning and exact factual labels live there; target dimensions live authoritatively in session.json. References include original/invented provenance and explicit redistribution authority for supplied assets. Lock identifies explicit constraints/selected saved baseline, not inferred preferences. Structural check never certifies factual accuracy.
